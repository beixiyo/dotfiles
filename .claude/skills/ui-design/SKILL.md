## 设计原则
- 先判断产品类型，再决定信息密度和视觉表达
- 工具、后台、CRM、IDE、数据面板优先扫描效率、重复操作效率和状态可读性
- 官网、作品集、品牌页优先视觉表达、节奏、留白和第一屏记忆点
- 使用项目现有设计 Token 和样式系统（如 `tailwind.config.js`、CSS 变量），先查实际配置，不假设配置文件名或技术栈

## 要求
- 信息架构：优先核心任务，次要功能延迟呈现，导航轻量
- 视觉风格：冷静、现代、专业；具体风格服从产品类型和现有设计系统
- 交互逻辑：任务路径清楚，状态反馈明确，配置项分组可扫描

## 避免
无组织的密集信息、多个竞争主按钮、过度分隔线、难以阅读的小字窄行距，以及干扰任务的装饰。色彩数量、阴影和纹理服从设计目的，不设统一禁令

后台/工具类页面允许高密度，通过分组、对齐和状态反馈保持可读；筛选与排序按任务需要提供
